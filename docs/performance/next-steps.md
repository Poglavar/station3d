# Station3D performance next steps

Updated 22 September 2026. Read [audit.md](audit.md) for measurements, completed
work, scope and limitations. This is the single active performance backlog.
All numbered items below are **proposals, not implemented fixes**.

## Order of work

Fix the reproduced collision and terrain-evidence loading failures first. Establish a trustworthy
cross-mode baseline next. Then work on measured ground/streaming and long-frame
costs, one change at a time. Do not start a renderer rewrite or country-wide
baking project to solve these findings.

Effort includes implementation, focused tests and regression verification for one
experienced maintainer: S = up to one day, M = 2–4 days, L = 5–10 days, XL = a
separate project. These are estimates, not commitments. Payoff is potential and
scenario-specific; no percentage FPS gains are promised without paired evidence.

## Definition of each step

### P1 — unblock complete collision support

Reproduce both recorded city starts without changing terrain, disabling collision
or raising limits globally. The 8,000-triangle road/rail dressing cap is checked
after whole-profile selection; first record per-profile contribution, retained
coverage, generated bytes and native allocation time. Determine whether excess
comes from outside-bubble geometry, tessellation, many profiles, or a combination.

Prefer exact spatial filtering and cooperative, complete chunks under a combined
geometry/body/staging budget. Splitting an already truncated buffer is not a fix.
Keep all triangles needed by the protected support region, including seams and
vertical bands; preserve the predecessor until the complete replacement commits.
Expose road **and rail-publication** failures through loading diagnostics instead
of leaving an apparently healthy queue behind a timeout.

Tests: synthetic over-cap profiles; exact coverage at bubble/chunk boundaries;
old-support retention and rollback; source supersession; cancellation; complete
combined staging bounds. Then re-run Zagreb/Split car, coastal boat, city flight,
walking and rail. Passing one car start does not justify weakening the general
engine's support contract.

Treat the city-flight source block as a separate reproduction. Preserve the
failing road/profile, terrain request bounds, NoData/detail state and generation
dependencies in a fixture. Establish why a surface sample about 2.38 km from
the anchor lacks evidence. Correct preparation coverage or source scheduling
without substituting zero height, removing the road or bypassing the readiness
gate. Test an actual normal opening and subsequent land flight/landing, not the
apparently usable world revealed by timeout.

### P2 — make performance evidence reproducible

Record hashes of the actual served outputs, not just repository HEAD/version or
lockfile. Install/pack/vendor from the intended dependency before measuring;
the audit found a stale planner installation despite its correct lockfile.
Check emitted asset URLs against package/consumer manifests: optional regional
content must be explicitly supplied or not requested, rather than returning a
collection of silent 404s. Do not invent replacement/licensing assumptions.

Keep a common stats-off frame observer with page-timed motion, actual controller,
distance, surface publication/coverage and error gates. Record API fixture hashes,
network totals by correct `/vendor/station3d*` paths, cache state, code fingerprints,
viewport, DPR, GPU backend and host memory pressure. The old network classifier
missed the migrated vendor path; zero reported code bytes was false.

Use separate diagnostics for JS CPU samples, browser long tasks, renderer/GPU
work, cooperative queues and memory. The CPU contention probe is one signal,
not an isolation certificate. Preserve invalid/degraded runs with reasons.
Do not label a 20-second post-stop catch-up window “settled” unless it drained.

### P3 and P4 — finish less work, then split the expensive work

Record why each generation was invalidated, which owner/receiver/region changed,
which result survived, and which candidate was superseded before publication.
Coalesce compatible pending changes; preserve current observer support and a
bounded route-ahead window. Cache only results with complete source/policy/
generation identity. Never drop a forced rebuild just because a replacement
request superseded its producer.

For a proven long operation, measure the indivisible section first. Cooperative
queues already exist. A worker can remove CPU preparation but not all GPU upload,
native collider creation or atomic publication costs. Split preparation/native
allocations, bound bytes per admission and keep the commit small. Do not increase
interactive budgets as a substitute for bounding items; that previously regressed
stationary performance. Validate both frame tails **and** finite queue completion.

Instrument the sampled geometry-attribute path with update/version outcomes,
buffer bytes and layer/caller identity. It is currently wrong to equate its
weighted CPU-profile samples with GPU transfer time. Independently examine
the observed tile-delivery and ground-generation long intervals; keep stats-off
verification separate from expensive diagnostic evidence collection.

### P5 and P6 — specialize policy without forking world behavior

A local-ready token must prove compatible visible ground, rail/road receivers,
backstops and required collision under the observer. It must carry generation
identity and survive late source arrivals; a single old publication count is
insufficient. Distant detail can finish later only if it is not required for the
current view or next safe movement.

Use speed, stopping/landing horizon, camera view and control capabilities to
choose bounded lookahead and detail admission in the common engine. Current
roads/curbs already look 1,400 m ahead; buildings use 800 m, or 900 m in GTA;
shared ahead retention is bounded. “Add prefetch” is not the missing feature.
Test sharper turns, reverse travel, high-speed flight over land, approach/landing,
boat-to-shore, entering/exiting vehicles and every relevant controller handover.
An open-water flight near display refresh is not justification for removing
terrain or support needed by a landing aircraft.

### P7 and P8 — render and retain only what is needed

Use a drained fixed view and time-adjacent ABBA diagnostic experiments to isolate
pixel/shadow cost, material/draw overhead and sparse instance processing. Hiding
a group is a diagnostic, not an acceptable optimization. Preserve equivalent
scenery, picking, proposal edits, visibility and source coverage in the candidate.
Building material batching, ordinary rail cells and distant-tram rejection are
already implemented; do not spend a new project recreating them.

The fresh fixed-view experiment gives buildings the strongest exploratory
signal, DPR a smaller one and sparse lamps no compelling priority. It also
exposed a passage-material shader that assumes `worldPosition` exists when
shadows are disabled. Isolating/fixing that supported shader-variant contract
is S–M effort, medium risk to authored openings, high correctness value but no
proven FPS gain. Do it before interpreting any new shadow-cost comparison;
do not remove passage clipping or globally disable shadows to pass a test.

Memory acceptance needs fresh-process measurements plus repeated close/reopen,
GC-controlled retained-heap observations outside timing windows, worker/native
and GPU/resource accounting, bounded source/decoded caches and route out/back.
Use a warmed closed-session baseline; retained shared renderer resources are not
automatically leaks. A lower quality tier may have a smaller atlas budget already;
do not silently change everyone's default to make a benchmark pass.

Before pursuing a leak project, reproduce the two fresh reopen `isReady`
exceptions with stacks. Test delayed callbacks, cancellation and old-session
work after close, including close while terrain/building preparation is active.
Do not infer the owner or add a blind optional-chain guard from the message alone.
The audit's short lifecycle test released most resources but did not pass the
error gate; memory counts do not excuse lifecycle faults.

### P9 — keep small ideas small

`processedItems` counts cooperative attempts, not completed jobs. Separate
completion/repeat/dependency-wait statistics before optimizing apparent volume.
Wake or back off genuinely blocked work without starving visible delivery.
`otherTrainsFn()` can be called separately by rendering and boarding; a common
immutable per-frame snapshot is a small candidate only if profiling establishes
duplicate expensive work. Keep provider/source identity and freshness explicit.

## Deferred or rejected directions

| Idea | Decision and reason | Reconsider only when |
| --- | --- | --- |
| Server-baked/precomputed whole world | **Deferred, not a demonstrated performance win.** Historical fully built on/off pairs did not show a consistent advantage and increased transferred/decoded payload. It does not remove texture residency, GPU uploads or driver stalls. | A bounded pilot with versioned source identity, visual/entity/collision parity, lifecycle and paired measurements beats the current engine. No country-wide preload or infrastructure migration is implied. |
| Road `BatchedMesh` prototype from July | **Rejected implementation.** Missed its draw/render gates, added triangles and removed selection/highlighting. Current owner-key batching supersedes it. | A different bounded prototype preserves semantics and demonstrates a measured win. |
| ECS/WebGPU/engine rewrite as the next optimization | **No current justification.** It does not directly address the reproduced support-capacity failure or prove lower publication latency. | A narrower measured bottleneck cannot be solved inside the present architecture. |
| Globally fewer layers, lower quality, larger work budgets or unlimited caches | **Rejected shortcuts.** They trade away correctness/appearance or move cost into other modes and memory pressure. | An explicit product quality choice or a measured bounded policy, not a benchmark-only switch. |
| More tram culling / first-time building batching / ordinary rail chunking | **Already done.** Old proposals described an earlier engine. | A new profile identifies a remaining specific exception, such as structural rail culling. |
| Time-based cab smoothing as an FPS fix | **Not established.** Adapter height/pitch consistency was fixed downstream; visual stability is separate from throughput. | A current cadence-dependent wobble is reproduced, with pose correctness checked first. |
| Zebra ownership, crossing envelopes, rail material appearance, campaign-pack visual parity | **Open correctness/appearance follow-ups, not ranked performance wins.** Preserve the relevant regression cases without reviving the old delivery tracker. | Scope them as correctness work and require the same no-performance-regression gates. |

## Acceptance and maintenance

For each change, update its row here and the corresponding measured finding in
[audit.md](audit.md). “Done” requires code, focused deterministic tests and the
relevant measured cross-mode result—not a green isolated microbenchmark.

The minimum regression matrix is dense walking (human and explorer speed), rail
through stations/turnouts and terrain seams, slow road traffic/curbs, coastal
boat/shore transitions, and fast land flight with approach/landing. Include
Prijevoz and planner packaging plus OSM checker and Consensus Builder proposal
selection/overlay workflows when shared rendering/world APIs change.

Compare p50/p95/p99, >=50/100/250 ms events per minute, worst interval, startup
latency, actual distance/coverage, catch-up time, queue age/debt, requests/bytes,
resident resources and retained memory. Agree scenario-specific acceptance
thresholds before an experiment; retain prior source/candidate receipts. No mode
may lose support, scenery, selection or loading correctness to improve another.
Do not average away a regression or use a historical acceptance exception as a
universal permission for new hitches.

Keep exactly these two canonical Markdown performance documents. Put new raw
captures and compact evidence receipts in the existing performance artifact
locations. Old audits are recoverable from the recorded Git history, not a
second active backlog.
